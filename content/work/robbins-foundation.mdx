## The problem

Robbins Foundation Systems runs Google Ads to its site, which sits on Flywheel behind Cloudflare and had just been cleaned of malware. The ad landing pages were slow on phones, an AI chatbot showed an API key in the page source, and any redirect fix risked stripping the click IDs the ads team relies on.

## What I did

- Swapped the chatbot for a server-side version with the key held in a Cloudflare Worker, signed off by the ads manager, with a lead event for Tag Manager.
- Hardened Wordfence so it reads the real visitor IP behind Cloudflare, and removed leftovers from the infection: a planted cache drop-in, stray PHP files, an abandoned file manager and a fake plugin path hiding in saved Elementor widgets.
- Proved the host strips gclid and utm before WordPress sees them, so moved the http, www and trailing slash redirects to Cloudflare instead.
- After a 48-hour notice and written sign-off, staging first: one phone layout on all 8 ad pages, phone-sized hero images preloaded (197 KB to 57 KB), Elementor CSS moved to cached files, unused scripts removed, tracking untouched.
- During a host outage, proved it was server-side, escalated with the evidence, and checked all 8 ad pages with tracking intact once it came back.

## Result

Main content on the four slowest ad pages now shows **4 to 9 seconds sooner on a phone**, server response on a new ad click roughly halved, and every click ID still reaches the tracking.
